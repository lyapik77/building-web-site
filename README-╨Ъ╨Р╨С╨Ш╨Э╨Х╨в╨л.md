# Кабинеты: вход, клиент, менеджер, администратор

## Запуск
(логотипы лежат в `src/frontend/img`)
1. `npm install`
2. В `.env`: `PORT`, `SECRET_KEY` (опционально `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`; по умолчанию как раньше: buildingdb / postgres / 1234 / localhost / 5432).
3. `npm run dev` и открыть `http://localhost:PORT` — бек сам раздаёт сайт.
4. Первый администратор (регистрация создаёт только клиентов):
   `node src/backend/scripts/createAdmin.js admin@example.com 'Пароль' Имя Фамилия +79990000000`
5. Менеджеров и других админов создаёт администратор в панели → «Пользователи».

## Страницы
| URL | Что |
|---|---|
| `/login` | вход и регистрация клиента |
| `/staff-login` | вход для менеджеров и администраторов |
| `/account` | кабинет клиента: объекты, заявки, профиль |
| `/staff` | панель: заявки, объекты, пользователи |
| `/privacy` | политика конфиденциальности (шаблон: заполните жёлтые поля `[...]`) |

Тема (светлая/тёмная) переключается кнопкой в шапке на всех страницах, выбор хранится в браузере; по умолчанию берётся системная. Логика — `script/theme.js`, цвета — переменные в начале `style/style.css`.

Как выложить сайт в интернет — в `DEPLOY.md`.

Если фронт открывается не с сервера бека (Live Server и т. п.), добавьте в `<head>` страниц
`<meta name="api-base" content="http://localhost:4000/api">`.

## Права
- Клиент: свой профиль, свои заявки и объекты.
- Менеджер: заявки (смена статуса), объекты (создание, статус, привязка клиентов), список пользователей.
- Администратор: всё это + удаление заявок/объектов/пользователей, смена ролей, создание пользователей.

## Изменения в бекe
- `checkRole('ADMIN','MANAGER')` теперь пускает любую из ролей (раньше только первую).
- Регистрация игнорирует `role` из запроса (раньше любой мог стать ADMIN); пароль ≥ 6 символов; email в нижнем регистре; дубликат → 409.
- Логин/регистрация возвращают `{ token, user }`; в JWT теперь есть `id`; `/user/auth` возвращает свежий токен и пользователя.
- Пароли больше не отдаются в `/user/users` и `/user/usersEmail`.
- Исправлены `PUT /request/updateStatus/:id` и `PUT /object/update/:id` (раньше `:id` не было в маршруте); валидация статусов; `findName` стал POST (GET с телом не работает в браузере).
- `deleteRequest` при ошибке возвращал 200 — теперь 404/500. `authMiddleware` больше не падает на невалидном токене.
- Новые: `GET/PUT /user/me`, `PUT /user/me/password`, `POST /user/create`, `PUT /user/:id/role`, `GET /request/my`, `GET /object/my`, `POST /object/:id/users`, `DELETE /object/:id/users/:userId`, `DELETE /object/:id`.
- Заявка с сайта от авторизованного клиента привязывается к его аккаунту (`UserId`).
- Параметры БД читаются из `.env` (значения по умолчанию прежние).
